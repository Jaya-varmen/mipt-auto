# MIPT Auto — приложение macOS и Windows

Графический интерфейс на Python + PySide6, браузерная автоматизация Playwright,
локальная база SQLite и аккаунты с паролями в `accounts.csv`.

## Запуск

Откройте **`MIPT Auto.app`** двойным щелчком в папке проекта. Сначала появляется
окно программы: аккаунты, режим, задержки и журнал. Браузер запускается после
нажатия «Запустить».

Альтернативы:

```bash
cd /path/to/Mipt-auto
.venv/bin/mipt-auto
# или
.venv/bin/mipt-auto-gui
```

Также доступен `Запустить MIPT Auto.command`. Локальный `.app` использует
`.venv` и файлы рядом с собой: пока не переносите его отдельно из папки проекта.
Это рабочий локальный launcher, не автономный подписанный дистрибутив.

## Выбор курса

Кнопками «Курс» выберите **8–9 класс** или **10–11 класс** до запуска. Один запуск
использует один курс для всех отмеченных аккаунтов. По умолчанию выбраны
10–11 класс и режим **«Выполнение очереди»**. Выбор курса запоминается отдельно
в локальных настройках.

Для 8–9 класса адрес курса и название первого модуля взяты из предоставленного
PDF. Профиль `config/edu-8-9.json` использует те же элементы списка и редактора,
что проверенный профиль 10–11 класса. Их совпадение на живой странице 8–9 ещё
нужно подтвердить чтением списка под авторизованным аккаунтом. Решения в JSON
должны иметь `course_key: "python-8-9"`; для старшего курса остаётся
`"python-10-11"`. Программа проверяет также ID и точное название задачи.

## Обновления

Версия показана в заголовке окна. Кнопка «Проверить обновления» использует
публичный репозиторий `Jaya-varmen/mipt-auto`. Для другой копии проекта можно
создать локальный `update-source.json` по образцу `update-source.example.json`.
Этот файл исключён из Git.

Программа проверяет последний GitHub Release, выбирает архив для macOS arm64 или
Windows x64, сверяет SHA-256, скачивает его в `data/updates`, закрывается и
запускает отдельный установщик. Он заменяет только файлы программы, обновляет
зависимости в текущем Python-окружении и перезапускает окно. При ошибке установки
исходные файлы восстанавливаются. Во время выполнения очереди обновление недоступно.
`accounts.csv`, `solutions.local.json`, `config.local.json`, `config.windows.json`,
`config.windows.8-9.json`, настройки и `data` не входят в архивы обновлений.

Для выпуска версии в `pyproject.toml` и `src/mipt_auto/__init__.py` должны
совпадать. При публикации новой версии в ветку `main` workflow
`.github/workflows/release.yml` запускает проверки и создаёт выпуск `vX.Y.Z`
с двумя архивами из `scripts/build_release.py`. Если такой выпуск уже есть,
повторная публикация в `main` не заменяет его. Установку этой версии на три
компьютера нужно выполнить один раз вручную.

## Аккаунты и CSV

Пустой файл **`accounts.csv`** уже создан:

```csv
email,password
```

Добавьте аккаунты по одной строке и нажмите **«Импорт CSV»**. Поддерживаются UTF-8,
UTF-8 с BOM, разделители запятая или точка с запятой. Значения с разделителем
внутри заключайте в двойные кавычки по правилам CSV. Пустой пароль допустим:
тогда вход выполняется вручную. Можно добавлять аккаунты прямо в окне.

Пароли сохраняются открытым текстом в `accounts.csv` рядом с программой.
Email также используются в SQLite для истории задач; пароли туда не записываются.
При добавлении аккаунта в окне CSV обновляется автоматически. Если вы правите
`accounts.csv` вручную, приложение подхватит изменения при запуске и перед
нажатием «Запустить». Для переноса между компьютерами копируйте этот файл.
`accounts.csv` исключён из Git. При импорте другого CSV его данные копируются
в основной `accounts.csv`.

Поставьте галочки у нужных email. В очередь попадут только отмеченные аккаунты.
Они обрабатываются последовательно. Для каждого создаётся новый BrowserContext;
cookies и авторизация не переносятся между аккаунтами и не сохраняются на диск.

Если поля Leader ID однозначно распознаны, программа заполнит email и пароль из
`accounts.csv` и попробует обычный вход. При CAPTCHA, дополнительной проверке или
изменении формы нужно завершить вход в браузере и нажать **«Продолжить после
входа»**. CAPTCHA не решается автоматически. Полностью автоматический вход с
реальными импортированными паролями зависит от проверки Leader ID; наличие
CAPTCHA и дополнительного шага определяется сайтом.

Стартовая страница входа в локальном профиле — `https://edu.mipt.ru/member`.
На ней используется кнопка «Войти с помощью Университета 20.35». Заполнение
полей Leader ID проверено на реальном экране; CAPTCHA или дополнительный шаг
остаётся оператору.

## Режимы

- **edu.mipt.ru · просмотр задач** — вход, открытие настроенного курса и чтение
  списка со статусами, без начала попыток.
- **edu.mipt.ru · выполнение очереди** — последовательная обработка по библиотеке
  решений. Пользователь подтвердил разрешение владельцев аккаунтов и администратора.
- **edu.mipt.ru · тест одной задачи** — один отмеченный аккаунт и один указанный
  ID. Если задача уже выполнена или в базе нет точного решения, запуск остановится.
- **Локальная демонстрация** — встроенные задачи, без реальных аккаунтов и оценок.
  Если база пуста, показывается временный `demo@example.test`; в реальную базу он
  не записывается. «Демо без ожидания» ускоряет только локальный стенд.

В окне видны текущий аккаунт, задача, прогресс, обратный отсчёт и журнал.
Playwright работает в отдельном потоке; интерфейс продолжает обрабатывать кнопки.

## Последовательность задач

1. Прочитать задачи выбранного модуля в порядке курса.
2. Пропустить задачи, отмеченные выполненными на сайте, а также задачи с ранее
   подтверждённым «Решение принято» для этого аккаунта в локальной истории.
3. Найти решение одновременно по курсу, ID и названию. Если записи нет —
   пропустить задачу без начала попытки; несовпадение названия останавливает запуск.
4. Открыть задачу и начать попытку.
5. Выдержать случайную паузу **1–4 минуты до ввода кода**, выбранную отдельно
   для каждой задачи. Диапазон задаётся в окне.
6. Вставить код, проверить его текст, подождать ещё **3–6 секунд**, затем один
   раз нажать «Проверить код» и дождаться подтверждённого результата.
7. После «Решение принято» перейти дальше. Проверенная кнопка следующей задачи
   используется, если её ссылка совпадает с ожидаемой задачей. Иначе используется
   прямой адрес из прочитанного списка курса.

Программа просматривает весь список задач модуля в порядке сайта. Если в JSON
есть решения только для 15 задач, остальные пропускаются без открытия попытки.
После конца модуля она переходит к следующему отмеченному аккаунту и начинает
его отдельную очередь. После последнего аккаунта завершает запуск.

После перехода программа ждёт устойчивого состояния страницы: кнопка начала
попытки должна оставаться видимой, а открытый редактор — сохраняться несколько
секунд. Это защищает от промежуточного состояния во время загрузки следующей задачи.

На реальном сайте нижняя кнопка следующей задачи ещё не наблюдалась, поэтому
текущий профиль использует прямые адреса. Это не возвращает программу к меню
перед каждой задачей.

Если после прерванного запуска попытка всё ещё открыта, программа распознаёт
видимый редактор и продолжает эту попытку без нового нажатия «Начать попытку».
Для уже идущей попытки пауза 1–4 минуты не повторяется, поскольку время её
начала неизвестно. Код вставляется, затем применяется пауза 3–6 секунд.
После открытия задачи программа кликает по видимой области кода, вводит решение
и проверяет его текст. Поиск редактора ограничен 30 секундами, ввод — 15; скрытое поле Monaco не служит
условием готовности. При ошибке окно браузера остаётся открытым: проверьте
попытку и нажмите в приложении «Закрыть браузер». Структура редактора без кода,
паролей и текста задачи сохранится в `data/editor-diagnostic.json`.
Диагностика включает элементы внутри открытого Shadow DOM.

Отказ, неизвестный результат или тайм-аут останавливают очередь. Повторной
отправки нет. **«Остановить»** прерывает ожидание перед отправкой. Уже отправленный
запрос отменить нельзя; его итог проверяется на сайте. Во время сетевого перехода
остановка может ждать до установленного тайм-аута навигации (30 секунд).
Если после клика результат не подтверждён, браузер остаётся открытым. Файл
`data/editor-diagnostic.json` содержит признак события клика, количество запросов
по методам и структуру области вывода без URL, кода и значений полей. Отсутствие
подтверждения за 45 секунд не означает истечения девятиминутной попытки.

Лимит 9 минут взят из указаний пользователя и задан в профиле. Задержка оставляет
запас на проверку; если настроен селектор фактического таймера, дополнительно
проверяется его значение. При недостаточном времени отправка прекращается.
Для задач с другим лимитом профиль нужно уточнить. Гарантии точности задержки
при сне компьютера или подвисании сайта нет; просроченная попытка не отправляется.

## База решений

В `solutions.local.json` пока одна запись — переданная пользователем задача
**1.1.3 «Эхо тестирующей системы»**:

```python
text = input()
print(text)
```

На проверенном аккаунте эта задача уже отмечена выполненной, поэтому очередь
её пропустит. Приложение не генерирует отсутствующие решения. Другую библиотеку
можно выбрать кнопкой в окне.

Для первой реальной проверки выберите невыполненную задачу в режиме просмотра,
узнайте её точный ID и название, добавьте запись в `solutions.local.json`
(или в отдельный JSON) и в окне выберите **«тест одной задачи»**. Отметьте ровно
один аккаунт, введите ID, затем нажмите «Запустить». Вход выполните в браузере
и нажмите «Продолжить после входа», когда вернётесь на платформу. Задержка
1–4 минуты отсчитывается после начала попытки. Успех должен появиться как
«Решение принято»; при неизвестном результате проверьте сайт вручную.

Формат:

```json
[
  {
    "course_key": "python-10-11",
    "task_id": "1.1.3",
    "title": "Эхо тестирующей системы",
    "code": "text = input()\nprint(text)\n"
  }
]
```

## Профиль сайта и фактическая проверка

`config.local.json` содержит адрес курса и наблюдавшиеся элементы. Копия профиля
без персональных данных — `config/edu-observed.json`.

В авторизованной сессии реально проверены: путь курса, контейнер Модуля 1,
120 задач, маркеры `check_yes` / `check_none`, заголовок задачи, кнопки начала
попытки и проверки, область редактора Monaco, панель «Вывод».
**Новая отправка на edu.mipt.ru ещё не выполнена.** Сопоставление надписи
«Решение принято» с панелью «Вывод» основано на описании пользователя и структуре
экрана; его ещё нужно подтвердить новой разрешённой отправкой. История старых
попыток исключена из этого поиска. Отдельный маркер отказа пока не установлен:
при отсутствии принятия будет тайм-аут и остановка, а не ложный успех.

Monaco заполняется клавиатурным вводом после клика по области кода. Полный текст
проверяется по доступной модели Monaco, EditContext или видимым строкам. Если
подтвердить вставку не удалось, отправки нет.

Настройки элементов поддерживают CSS либо точные `role` + `name`, либо `text`.
`scope_css` ограничивает область поиска. Внутренние селекторы `collection`
(`title_css`, `link_css`, `statuses`) должны быть стандартными CSS-селекторами.

Диагностика для следующих изменений сайта:

```bash
.venv/bin/mipt-auto inspect
```

Она сохраняет структуру без значений полей, cookies, токенов и произвольного
текста личного кабинета. Внутренность iframe требует отдельной проверки.

## Скорость

Пошаговое исследование сайта в чате не было скоростью готового приложения.
Теперь список задач считывается одним браузерным вызовом вместо нескольких
запросов для каждой строки. Используется проверенный прямой адрес курса;
переходы ожидают начало документа, затем конкретный нужный элемент, а не все
ресурсы страницы. Браузер переиспользуется между изолированными контекстами.

Журнал окна показывает время навигации до начала документа и время чтения списка.
Перед переходами между страницами в реальном профиле добавлена случайная пауза
5–10 секунд. Она не применяется во время активной попытки и не заменяет задержку
1–4 минуты перед вводом кода.
Ожидание 1–4 минуты отмечается как «Пауза перед вводом кода». Скорость сети,
ответ сервера и CAPTCHA остаются внешними факторами.

## Данные и журналы

`data/progress.sqlite3`: аккаунты без паролей, снимки задач и результаты с привязкой
к локальному ID аккаунта. `data/app.log`: ID запусков, состояния и технические
времена без паролей. `settings.local.json`: выбор аккаунтов, задержки и путь к
базе решений. Эти файлы исключены из Git.

Промежуточные состояния (`starting`, `delay`, `submitting`, `waiting`) после
принудительного завершения не означают успех. Автоматического возобновления
отправки нет. Историю можно посмотреть командой `.venv/bin/mipt-auto history`.

На этом Mac Qt считает плагины в `.venv` скрытыми. Перед запуском приложение
проверяет их и при необходимости копирует в `data/qt-plugins`. Этот локальный
кэш можно восстановить повторным запуском. Системные настройки macOS не меняются.

## Установка и тесты

### Windows 11, 64-разрядная версия

1. Установите Python 3.12 x64 с [python.org](https://www.python.org/downloads/windows/).
2. Скопируйте на ноутбук всю папку проекта с `accounts.csv`, выбранной базой
   решений JSON и `config.local.json`. Папку `.venv` и `MIPT Auto.app` переносить
   не нужно. Если в `accounts.csv` пока пусто, добавьте строки `email,password`.
3. В папке проекта запустите двойным щелчком `Windows-Setup.cmd`. Он установит
   зависимости и Chromium Playwright, создаст отдельные `config.windows.json`
   и `config.windows.8-9.json`
   и проверит локальную демонстрацию. Нужен интернет при первой установке.
4. Для работы запускайте `Windows-Start.cmd` из той же папки. Выберите аккаунты
   и базу решений в окне. Если импортированный JSON лежит в другом месте,
   укажите его кнопкой «Выбрать базу решений».

При ручном редактировании CSV сохраняйте файл в UTF-8. Пароли из старого macOS
Keychain в CSV автоматически не переносятся: внесите их один раз самостоятельно.

### macOS

На новом Mac с Python 3.10+ (предпочтительно 3.12):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[dev]'
```

Используется установленный Google Chrome. Для Chromium установите его через
`python -m playwright install chromium` и задайте пустой `browser_channel`.
Встроенный GUI-стенд по умолчанию использует Chrome.

```bash
MIPT_BROWSER_CHANNEL=chrome .venv/bin/python -m pytest -q
.venv/bin/mipt-auto demo --channel chrome --headless
```

Точные версии тестовых зависимостей — `requirements-dev.lock.txt`. Набор проверяет импорт и хранение
паролей в CSV, изоляцию браузеров, выбор галочек, два аккаунта в GUI-потоке, принятие /
отказ / тайм-аут, переход к следующей задаче, пропуск выполненных, диапазон
задержки, остановку до отправки и ввод через EditContext.

Источники архитектурных решений: [изоляция Playwright](https://playwright.dev/python/docs/browser-contexts),
[переходы](https://playwright.dev/python/docs/api/class-page#page-goto),
[потоки Qt](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QThread.html),
[EditContext](https://developer.mozilla.org/en-US/docs/Web/API/EditContext/text).
